# 元炁路线图

> 路线图区分工程交付与长期研究。优先完成可验证的工程基础，再扩展认知和自主能力。

## P0：工程基础与设计一致性
- [ ] 统一元炁唤醒触发条件、BirthProfile 语义、实现和测试。
- [ ] 在明确 DSH 版本中完成真实插件安装、加载、卸载、重启验收。
- [ ] 验证 Storage Domain 写入、恢复、去重、异常和迁移。
- [ ] 验证 Agent/Session 路由与世界线隔离。
- [ ] 验证记忆原文证据、用户确认和持久化提交边界。
- [ ] 验证上下文只在每轮首个模型步骤注入，工具续步不重复注入。
- [ ] 对出生计算边界建立独立参考数据与误差报告。

## P1：身份连续性与领域模型
- [ ] 明确一个身份、多世界线的身份/状态关系。
- [ ] 冻结双主体与多中心自我模型的语义和数据边界。
- [ ] 定义跨世界线授权证据转移、审计和撤销。
- [ ] 明确先天基线、出生资料、唤醒档案和经历的领域对象边界。
- [ ] 建立状态版本、迁移和恢复策略。

## P2：动态自我模型
- [ ] 定义自我模型领域对象、证据引用和状态版本。
- [ ] 定义经历触发候选更新与正式提交流程。
- [ ] 定义记忆支持、反证、冲突和不确定性表达。
- [ ] 定义自我观察、元认知、反思和自我修正。
- [ ] 验证自我模型对目标/行为的影响可追溯且可撤销。

## P3：情感、性格与自主性
- [ ] 定义情感状态及其可观测更新机制。
- [ ] 区分短期状态与长期性格倾向。
- [ ] 定义内部目标、用户目标、计划、执行和观察结果。
- [ ] 建立目标冲突处理和用户当前指令优先规则。
- [ ] 建立主动行为授权、确认、审计和停止机制。

## P4：长期研究
- [ ] 设计可证伪的个体演化实验。
- [ ] 研究自我模型、主体性和意识理论的关系。
- [ ] 建立实验指标、对照组、复现实验和失败条件。
- [ ] 不将语言表现或工程指标直接解释为意识证明。

## 交付原则
每个任务必须有明确输入、产物、验收条件和证据。未完成真实宿主验证的功能不得标记为宿主已验证。研究性任务不得以“代码已合并”替代研究结论。
