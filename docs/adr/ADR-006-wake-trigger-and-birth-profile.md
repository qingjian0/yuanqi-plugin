# ADR-006：唤醒触发与 BirthProfile

- 状态：Conflict
- 决策主题：元炁自身唤醒时间与用户出生资料必须分离；触发规则存在历史决策/当前实现冲突。

## 历史用户决策记录
历史项目上下文记录：首次安装后的第一次对话中，只有用户明确说出“启动元气”或“启动元炁”时，才建立元炁的 BirthProfile，并使用该次对话开始时间作为元炁唤醒时间。用户出生资料是独立数据，必须由用户提供并确认。

## 当前仓库描述
当前 main README 描述：插件安装后首次出现包含“元气”的 direct-user 消息时，使用该 DSH 事件时间记录元炁自身唤醒时刻；助手输出和注入上下文不会触发唤醒。

## 冲突
“首次包含元气”比“明确启动口令”宽泛，可能在普通提及元气时误触发。当前 README 规则不能自动覆盖历史用户明确决策。

## 暂定处理
在实现修复前将此能力标记为实现与决策冲突。不得静默更改用户决策。需要把触发条件、首次会话范围、重复消息、引用文本、助手消息、工具续步、时区/事件时间和幂等性写入测试。

## 相关概念
- YuanQiWakeRecord：元炁自身唤醒事件。
- UserBirthProfile：用户主动提供并确认的出生资料。
- InnateBaseline：由明确资料与计算规则建立的初始领域基线。

上述名称为建议的领域区分，不代表当前源码已采用这些类型名。
