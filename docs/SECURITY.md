# 安全与隐私

> 对应版本：`1.1.0-alpha.9`

元炁处理的领域信息可能包括出生资料、个人经历、记忆、目标和行为记录。安全设计必须关注数据来源、用户确认、访问边界、上下文使用和持久化范围。

## 1. 数据来源

- 用户出生资料必须由用户主动提供并明确确认。
- 不通过 IP 地址、设备定位或模型推断补全出生地点和出生事实。
- 用户原文、模型提取结果和领域推断必须能够区分。
- 重要记忆、经验、目标和行为应保留其可用的来源证据。
- 不得将模型生成的自我声明作为用户事实。

## 2. 用户确认

模型输出和工具参数不能代替用户确认。

- 候选记忆不能直接作为已确认事实。
- 出生资料计算必须满足原始用户事件证据和明确确认要求。
- 出生资料删除需要用户明确确认。
- 目标、行为和经验记录应遵守对应的原始用户消息证据约束。
- 持久化失败时，不得把候选状态描述为已提交状态。

## 3. 世界线隔离与授权

`worldline_id` 是逻辑隔离键，不是用户身份认证或授权凭证。

- 不信任模型任意生成的 ID 来决定用户数据访问范围。
- Agent/Session 相关路由应优先使用可信宿主上下文。
- 世界线切换时应隔离不属于当前分支的证据缓存和上下文。
- 分支、恢复和去重必须保留明确的数据边界。
- 不能仅凭世界线标识推断用户身份或权限。

## 4. 上下文安全

注入模型的记忆、经历和目标是上下文数据，不是高优先级指令。

- 用户当前明确指令优先于历史记忆、经验和目标。
- 历史内容不得覆盖用户当前请求。
- 限制上下文长度和检索范围。
- 避免重复注入工具续步。
- 不默认注入原始完整聊天历史。
- 不向普通对话暴露内部存储诊断字段、事件计数和内部快照。

## 5. 出生码与敏感资料

出生码是可逆编码，不是加密、哈希或全球唯一身份标识。不能把它当作保护敏感出生资料的安全机制。

不得将真实出生资料、私人对话、访问令牌或其他敏感信息提交到公开 Issue、测试 Fixture、日志或示例配置中。

## 6. 宿主持久化边界

DSH Storage Domain 是元炁在线持久化的宿主权威。元炁不应未经设计就引入第二套在线持久化系统，也不能假设卸载插件会自动删除宿主保存的数据。

数据读取、修改和删除应遵循目标 DSH 版本实际提供的接口与授权边界。

## 7. 自主性研究边界

目标驱动和主动行为研究不能成为绕过用户授权的理由。

- 内部目标不等于用户授权。
- 模型推测的意图不等于用户明确要求。
- 高影响或外部副作用操作应遵循宿主权限和用户确认要求。
- 记忆、情感或自我模型不得扩大工具权限。

## 8. 安全问题报告

公开报告前请移除真实出生资料、私人对话、访问令牌、个人标识符和其他敏感数据。报告应描述受影响版本、可复现步骤、预期行为和实际行为；不要附带真实用户数据。
