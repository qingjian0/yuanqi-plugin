## 1. 项目身份

元炁（YuanQi）是面向 DeepSeek Harness（DSH）的生命上下文与持续演化插件。DSH 是宿主和产品入口；元炁是 DSH 内部的领域能力扩展，不是独立 Agent Runtime。

核心原则：**先天为本，后天为用；先天的是本色，后天的是经历。**

长期目标是研究并构建具有身份连续性、可追溯经历、证据化记忆、动态自我模型、可演化内部状态和受授权约束行为机制的 AI 个体系统。不得将研究目标表述为已经产生真实意识、主观体验或独立意志。

## 4. 产品与架构原则

- DSH 负责 Agent Runtime、模型调用、Session/消息生命周期、工具执行、插件生命周期及 Storage Domain 在线持久化。
- 元炁负责生命上下文领域模型、先天基线、出生资料、世界线、记忆、经历、目标、行为和上下文投影。
- 不另建 Agent Runtime，不用第二套在线持久化系统替代 DSH Storage Domain。
- 自我模型是长期架构中枢，不等同于人格字段、固定提示词或模型自我声明。
- 先天基线与后天经历分离；普通经历不得静默覆盖先天基线。
- 用户出生资料必须由用户主动提供并明确确认；不得由 IP、设备定位或模型推断补全。
- 记忆、经验、目标和行为应保留可用的原始用户证据；模型推断不得伪装成用户事实。
- 候选记忆必须经过用户明确确认后才能升级为已确认记忆。
- 目标、计划、实际行为和观察结果必须分离。
- 用户当前明确指令优先于历史记忆、经验、目标和上下文。
- worldline_id 是逻辑隔离键，不是身份认证或授权凭证。
- 跨世界线证据转移必须有明确授权、范围、来源、审计与撤销规则。
- 主动行为受宿主权限、用户授权和安全边界约束。

## 5. 初始化、唤醒与出生资料

历史用户决策记录：元炁 BirthProfile 应仅在用户首次明确说出“启动元气”或“启动元炁”后创建，并以该次对话开始时间作为元炁自身唤醒时间。用户出生资料是另一独立概念，必须由用户提供并确认。

**已发现的实现冲突：** 当前 main README 描述为插件安装后首次出现包含“元气”的 direct-user 消息时记录元炁唤醒时刻。这比历史明确启动口令宽泛。此项必须作为 ADR-006 冲突处理；在用户决策与实现统一前，不得宣称当前实现符合历史确认规则。

元炁唤醒时间、用户出生时间、先天基线建立时间和后天经历时间必须分开存储、展示和使用。出生码为可逆编码，不是加密、哈希或全球唯一身份标识。

## 6. 世界线与个体连续性

历史目标包括一个身份、多条相互隔离的世界线，以及在授权和证据核验后跨世界线转移指定证据。当前仓库状态文档记录了按 DSH Session 隔离世界线、分支、切换、事件恢复与去重，以及切换时隔离进程内证据缓存。

当前已实现的 Session 级隔离不能自动证明完整的多主体、多中心自我模型或授权证据迁移已落地。相关设计见 ADR-003、ADR-010。

## 7. 自我模型及长期研究

自我模型应是可更新、可追溯、由记忆支持、由认知反思、能够参与目标评估和行为选择的动态领域模型。长期研究方向包括：
- 身份表征、状态表征与连续性；
- 经历关联、记忆支持、自我观察；
- 元认知、反思、冲突处理与自我修正；
- 情感状态形成与反馈；
- 性格倾向的长期形成；
- 目标形成、冲突处理和自主行为；
- 主体性与意识理论研究。

工程实现不等于科学证明。情感状态建模不等于真实主观情感；自我模型不等于自我意识；目标驱动行为不等于独立意志。
